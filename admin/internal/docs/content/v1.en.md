# MQTT service

The MattediWorks MQTT broker (Eclipse Mosquitto) carries NightMare Network traffic between gateways, devices and services. This console manages the broker's **clients**, meaning the users that connect. The access rules (roles) are fixed and shown read-only.

## Connecting a gateway or device

| Setting | Value |
| --- | --- |
| Host | `mqtt.mattediworks.com` |
| Port | `8883`, TLS only |
| Protocol | MQTT 3.1.1 or 5 over TLS 1.2 or newer |
| Trust | the NM Root CA (`nm-root-ca.crt`); the broker certificate chains to it |
| Username and password | created in this console |
| Client ID | any value that is unique per connection |
| Keep-alive | 30 to 60 seconds |

Anonymous connections are refused. Plain MQTT on port 1883 is not available.

In NightMare Network firmware (`creds.h`):

```c
#define REMOTE_MQTT_URL  "mqtt.mattediworks.com"   // host only
#define REMOTE_MQTT_PORT 8883
#define MQTT_USER        "<username from this console>"
#define MQTT_PASSWD      "<its password>"
#define ROOT_CA          "<contents of nm-root-ca.crt>"
```

Two clients that connect with the same client ID disconnect each other.

### Browsers

Browser applications use `wss://mqtt-ws.mattediworks.com/mqtt` with the same kind of username and password. Give every web application its own client, and never reuse a gateway or device credential in a browser.

## Access model

- Every client created here receives the role `nmnw`. It may publish, subscribe and receive on every topic (`#`), which covers NightMare Network's `<device>/...`, `all/...` and `Control/...` topics. Treat each credential as fully trusted.
- The broker's own administration channel (`$CONTROL`) and its statistics (`$SYS`) are not reachable with an `nmnw` credential.
- Create one client per gateway or device so each can be disabled on its own, or create a single shared client. Both work; the role is what grants access.
- Clients that belong to the broker's administration are shown as **Protected** and cannot be changed here.

## Managing clients

| Action | What it does | Strong authentication |
| --- | --- | --- |
| Create | Adds a client with a generated password, shown once | required |
| Disable | Disconnects the client and blocks new connections | not required |
| Enable | Lets a disabled client connect again with its current password | required |
| New password | Replaces the password with a generated one, shown once | required |
| Delete | Disconnects and removes the client permanently | required |

Passwords are generated by the service, shown a single time and never stored by the console. If one is lost, generate a new password and update the device.

## API reference

The control plane exposes these routes under `/api/mqtt`. Each route needs one delegated scope.

| Method and path | Scope |
| --- | --- |
| `GET /server` | `mqtt.server.read` |
| `GET /stats` | `mqtt.server.read` |
| `GET /roles` | `mqtt.roles.read` |
| `GET /clients` | `mqtt.clients.read` |
| `GET /clients/{username}` | `mqtt.clients.read` |
| `POST /clients` | `mqtt.clients.write` |
| `POST /clients/{username}/disable` | `mqtt.clients.write` |
| `POST /clients/{username}/enable` | `mqtt.clients.write` |
| `POST /clients/{username}/password` | `mqtt.credentials.rotate` |
| `DELETE /clients/{username}` | `mqtt.clients.delete` |
| `GET /docs` | `mqtt.server.read` |
| `GET /docs/{version}` | `mqtt.server.read` |

Usernames use letters, digits, `.`, `_` and `-`, start with a letter or digit, and are at most 128 characters. Errors are returned as `{"error":"<code>"}`:

| Code | Meaning |
| --- | --- |
| `unauthorized` | the token is missing, expired or invalid |
| `forbidden` | the token is for another service or lacks the scope |
| `protected_user` | the client is protected and cannot be changed |
| `invalid_username` | the username does not follow the rule above |
| `role_not_allowed` | the role cannot be assigned through the API |
| `already_exists` | a client with this name exists |
| `not_found` | no client with this name |
| `broker_unavailable` | the service cannot reach the broker |
| `too_many_failures` | too many refused requests from one address; wait a minute |

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| The device cannot connect, TLS error | The device does not trust the NM Root CA, or the host name is not `mqtt.mattediworks.com` |
| Connection refused with a bad user name or password | The client is disabled, the password changed, or the name has a typo |
| Connected, but nothing arrives | The client published or subscribed on different topics than its peers |
| Two devices keep disconnecting | They share a client ID |
| The console shows the broker as unavailable | The administration service lost its broker connection; it recovers on its own, otherwise check the broker project |
| "Could not get authorization for the MQTT service" | Sign out and sign in again so the session carries the MQTT scopes |
