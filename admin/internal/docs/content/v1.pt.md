# Serviço MQTT

O broker MQTT da MattediWorks (Eclipse Mosquitto) transporta o tráfego da NightMare Network entre gateways, dispositivos e serviços. Este console gerencia os **clientes** do broker, ou seja, os usuários que se conectam. As regras de acesso (funções) são fixas e aparecem somente para leitura.

## Conectando um gateway ou dispositivo

| Configuração | Valor |
| --- | --- |
| Host | `mqtt.mattediworks.com` |
| Porta | `8883`, somente TLS |
| Protocolo | MQTT 3.1.1 ou 5 sobre TLS 1.2 ou superior |
| Confiança | a NM Root CA (`nm-root-ca.crt`); o certificado do broker é emitido a partir dela |
| Usuário e senha | criados neste console |
| Client ID | qualquer valor único por conexão |
| Keep-alive | 30 a 60 segundos |

Conexões anônimas são recusadas. MQTT sem criptografia na porta 1883 não está disponível.

No firmware da NightMare Network (`creds.h`):

```c
#define REMOTE_MQTT_URL  "mqtt.mattediworks.com"   // somente o host
#define REMOTE_MQTT_PORT 8883
#define MQTT_USER        "<usuário criado neste console>"
#define MQTT_PASSWD      "<a senha dele>"
#define ROOT_CA          "<conteúdo de nm-root-ca.crt>"
```

Dois clientes que se conectam com o mesmo client ID desconectam um ao outro.

### Navegadores

Aplicações web usam `wss://mqtt-ws.mattediworks.com/mqtt` com o mesmo tipo de usuário e senha. Dê a cada aplicação web o seu próprio cliente e nunca reutilize a credencial de um gateway ou dispositivo em um navegador.

## Modelo de acesso

- Todo cliente criado aqui recebe a função `nmnw`. Ela pode publicar, assinar e receber em todos os tópicos (`#`), o que inclui os tópicos `<dispositivo>/...`, `all/...` e `Control/...` da NightMare Network. Trate cada credencial como totalmente confiável.
- O canal de administração do broker (`$CONTROL`) e as suas estatísticas (`$SYS`) não são acessíveis com uma credencial `nmnw`.
- Crie um cliente por gateway ou dispositivo para poder desativar cada um separadamente, ou crie um único cliente compartilhado. Os dois funcionam; é a função que concede o acesso.
- Clientes da administração do broker aparecem como **Protegido** e não podem ser alterados aqui.

## Gerenciando clientes

| Ação | O que faz | Autenticação forte |
| --- | --- | --- |
| Criar | Adiciona um cliente com senha gerada, exibida uma única vez | exigida |
| Desativar | Desconecta o cliente e bloqueia novas conexões | não exigida |
| Ativar | Permite que um cliente desativado volte a se conectar com a senha atual | exigida |
| Nova senha | Substitui a senha por outra gerada, exibida uma única vez | exigida |
| Excluir | Desconecta e remove o cliente permanentemente | exigida |

As senhas são geradas pelo serviço, exibidas uma única vez e nunca armazenadas pelo console. Se uma for perdida, gere uma nova senha e atualize o dispositivo.

## Autenticação

Toda requisição a `/admin/api` carrega um token bearer: `Authorization: Bearer <token>`. A forma como os tokens são emitidos depende do `ADMIN_AUTH_MODE` do serviço:

| Modo | Use quando | De onde vem o token |
| --- | --- | --- |
| `token` (padrão) | o serviço roda sozinho | um token estático gerado para você ou para um job; só o hash dele é configurado |
| `federated` | há um provedor de identidade com introspecção de tokens na frente | um token de curta duração que o provedor emite por pessoa e ação |

No modo token, o operador gera um token com `mqtt-admin token new --name <nome> --scopes <read|write|admin> [--expires AAAA-MM-DD]` e adiciona a entrada impressa em `MQTT_ADMIN_TOKENS`. O token é exibido uma única vez e não pode ser recuperado. Um token tem escopos, um preset ou nomes de escopo separados por `+`:

| Preset | Concede |
| --- | --- |
| `read` | `mqtt.clients.read`, `mqtt.roles.read`, `mqtt.server.read` |
| `write` | `read`, mais `mqtt.clients.write` e `mqtt.credentials.rotate`; sem exclusão |
| `admin` | todos os escopos, inclusive `mqtt.clients.delete` |

Quando o serviço é chamado diretamente, as rotas abaixo ficam em `/admin/api/`, por exemplo:

```sh
curl -H "Authorization: Bearer $TOKEN" https://<host-admin>/admin/api/clients
```

A autenticação forte (uma verificação recente de passkey antes de criar, reativar, trocar a senha ou excluir um cliente) não é feita pelo serviço. O control plane da MattediWorks a aplica na frente da API. No modo token, um token de escrita roubado é suficiente; por isso dê tokens de leitura às pessoas, reserve tokens de escrita para poucas pessoas ou jobs e defina uma data de expiração.

## Referência da API

Atrás do control plane da MattediWorks estas rotas ficam em `/api/mqtt`; chamadas diretamente ficam em `/admin/api`. Cada rota exige um escopo.

| Método e caminho | Escopo |
| --- | --- |
| `GET /server` | `mqtt.server.read` |
| `GET /stats` | `mqtt.server.read` |
| `GET /roles` | `mqtt.roles.read` |
| `GET /clients` | `mqtt.clients.read` |
| `GET /clients/{username}` | `mqtt.clients.read` |
| `POST /clients` | `mqtt.clients.write` |
| `POST /clients/{username}/disable` | `mqtt.clients.write` |
| `POST /clients/{username}/enable` | `mqtt.clients.write` |
| `POST /clients/{username}/password` | `mqtt.credentials.rotate` |
| `DELETE /clients/{username}` | `mqtt.clients.delete` |
| `GET /docs` | `mqtt.server.read` |
| `GET /docs/{version}` | `mqtt.server.read` |

Nomes de usuário usam letras, dígitos, `.`, `_` e `-`, começam com letra ou dígito e têm no máximo 128 caracteres. Os erros são retornados como `{"error":"<código>"}`:

| Código | Significado |
| --- | --- |
| `unauthorized` | o token está ausente, expirou ou é inválido |
| `forbidden` | o token é de outro serviço ou não tem o escopo |
| `protected_user` | o cliente é protegido e não pode ser alterado |
| `invalid_username` | o nome não segue a regra acima |
| `role_not_allowed` | a função não pode ser atribuída pela API |
| `already_exists` | já existe um cliente com este nome |
| `not_found` | não existe cliente com este nome |
| `broker_unavailable` | o serviço não consegue alcançar o broker |
| `too_many_failures` | muitas requisições recusadas de um mesmo endereço; aguarde um minuto |

## Solução de problemas

| Sintoma | Causa provável |
| --- | --- |
| O dispositivo não conecta, erro de TLS | O dispositivo não confia na NM Root CA, ou o host não é `mqtt.mattediworks.com` |
| Conexão recusada por usuário ou senha inválidos | O cliente está desativado, a senha mudou ou o nome tem um erro de digitação |
| Conectado, mas nada chega | O cliente publicou ou assinou em tópicos diferentes dos seus pares |
| Dois dispositivos ficam se desconectando | Eles compartilham o mesmo client ID |
| O console mostra o broker como indisponível | O serviço de administração perdeu a conexão com o broker; ele se recupera sozinho, caso contrário verifique o projeto do broker |
| "Não foi possível obter autorização para o serviço MQTT" | Saia e entre novamente para que a sessão carregue os escopos MQTT |
